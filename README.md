# CSVレスキュー v5 — Shift_JIS（Windows-31J / CP932）出力対応

公開先： https://csv-rescue-tool.pages.dev/

## v5の追加内容
- 「出力文字コード」に **Shift_JIS（Windows-31J / CP932）** を追加。UTF-8（BOM付き／なし）は引き続き選べます。
- ブラウザ標準のShift_JISデコード表から逆引き対応表を作成。外部ライブラリ・CDNは不要で、処理はブラウザ内だけで完結します。
- 指定した文字コードで**表現できない文字を事前検知**。件数と行・列の例を表示し、初期状態ではダウンロードを無効化します。
- 利用者が明示的に選んだときだけ、表現できない文字を `?` に置換して保存できます（情報が失われます）。
- 解説ページ `csv-to-shift-jis.html`、テストデータ `sample-encoding.csv` を追加。サイトマップ・FAQ・内部リンクを更新しました。
- 既存のAdSense用スクリプト、`ads.txt`、Google Search Consoleの認証タグ、問い合わせ先、プライバシーポリシー、全v4機能を維持しています。

## 更新方法（GitHub + Cloudflare Pages）
1. まずGitHubのリポジトリから **Code → Download ZIP** でバックアップを取得してください。
2. 配布ZIPを解凍し、**内側のファイルをすべて** GitHubの `rexsf7/csv-rescue-tool` リポジトリのトップ階層へアップロードします。ZIPファイルや外側のフォルダはアップロードしません。
3. `index.html` や `app.js` は上書き更新、`csv-to-shift-jis.html` と `sample-encoding.csv` は新規追加です。`Commit changes` を押します。
4. Cloudflare Pagesの最新のデプロイが `Success` になることを確認します。GitHub連携済みなら再設定は不要です。
5. 公開ページで `Ctrl + Shift + R` を押し、下記の動作確認をしてください。

## 動作確認
1. `sample.csv` を読み込んで診断し、「出力文字コード」で Shift_JIS を選択。ダウンロードして文字コード指定で開き、日本語が正しく表示されることを確認。
2. `sample-encoding.csv` で診断して Shift_JIS を選ぶと、絵文字😀を変換できないという警告が出て、ダウンロードが無効になることを確認。
3. 「? に置換して保存する」をチェックするとダウンロードが有効になることを確認。保存したCSVでは絵文字が `?` に変わっていることを確認。
4. 再びUTF-8（BOM付き）に切り替えると、元の絵文字を保持して保存できることを確認。
5. これまでの重複行削除、指定列重複判定、列抽出、CSV⇔TSV変換も維持されることを確認。
6. `/ads.txt`、`/sitemap.xml` と新規ページ `/csv-to-shift-jis.html` が開けることを確認。

## 仕様と注意点
- このバージョンでは「Shift_JIS」という名称の**Windows-31J / CP932互換**出力を実装しています。受け取り先の厳密なShift_JIS仕様とは異なる場合があります。
- 変換可能の判定はブラウザのWHATWG Shift_JISマッピングに基づきます。Windows機種依存文字については取り込み先のソフトで再確認してください。
- Unicodeの絵文字、異体字などの一部は表現できません。初期状態では文字の無断置換を避けて保存を停止します。
- ブラウザによる読み込み時点で誤った文字コードを選んだ場合や、既に破損・置換済みの文字は修復できない場合があります。
- 保存はタブ区切りTSVにも対応しますが、出力データは必ず目的のアプリで検証してください。
- CSVのセルはユーザーのブラウザ内のみで処理し、サーバーにはアップロードしません。ただしAdSenseなどの第三者スクリプトが読み込まれる場合があります（プライバシーポリシー参照）。
- Google AdSenseの審査や検索順位、収益は保証されません。
